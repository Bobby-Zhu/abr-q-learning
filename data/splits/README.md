# Deterministic trace splits

The split manifests contain paths relative to `data/` and are generated by
`scripts/create_splits.py`.

| Split | FCC | HSDPA | Total | Purpose |
| --- | ---: | ---: | ---: | --- |
| Training | mixed upstream set | mixed upstream set | 166 | Q-table updates and baseline development |
| Validation | 43 | 86 | 129 | State-bin and hyperparameter selection |
| Test | 45 | 88 | 133 | Final frozen comparison only |

The upstream training directory remains the training split. The 262 upstream
holdout traces are consecutive slices of 39 longer recordings, named
`<recording>_part<N>.log`. They are classified by filename (`trace_` for FCC,
all others for HSDPA) and grouped by recording. Within each source, recordings
are ranked using SHA-256 of `42:<recording>`, and each whole recording is
assigned to whichever of validation or test currently has fewer traces. This
keeps every slice of a recording in one split, so validation and test never
share neighbouring minutes of the same trip, and it does not rely on Python's
random-number implementation. Split sizes are therefore close to, not exactly,
equal.

`create_splits.py` refuses to write manifests in which any recording appears in
more than one split.

Regenerate or verify the manifests with:

```bash
python3 scripts/create_splits.py
python3 scripts/create_splits.py --check
```

Do not tune policies, state bins, or Q-learning hyperparameters using
`test.txt`.
